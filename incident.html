System Architecture
v2.4 · Production
Privacy Layer

Zero-Trust PII Deconstruction

Three detection layers: structural NLP, a local neural model (BERT-Small ONNX), and a statistical anomaly filter: identify and tokenize all PII on-device before any text reaches the cloud. Identity maps exist only in RAM: never written to disk, never transmitted.

Extraction Engine

Multi-Pass Atomic Extraction

8 semantic field groups processed independently: datetime, location, personnel, severity, emergency services, actions, cause, documentation. Confidence floor: 0.50.

→ date & time extraction
→ location & area mapping
→ personnel & witness identification
→ severity assessment
→ emergency services check
→ actions taken
→ cause & outcome analysis
→ documentation & evidence
Integrity

SHA-256 Cryptographic Anchoring

Every completed report is fingerprinted at export. Post-export modifications are detectable. Append-only. Immutable.

Architecture

THE SYSTEM DECIDES.
THE MODEL
ASSISTS.

Tidemark does not let an AI improvise its way through an incident report. A deterministic state machine controls what gets asked, what gets accepted, and when the report is actually complete.

account_tree

AI On A Leash

The orchestrator is the control layer. It decides the next question, checks whether a field is good enough to keep, and determines when a report is complete. The model helps extract facts. It does not set the standard.

radar

Confidence Gate

If the model is not confident enough, the field is rejected and the system asks explicitly. Polished guessing is not allowed into the record.

Discard Accept ≥ 0.50
rule

Playbook-Led Completion

The playbook decides what is required for that incident type. Completion is computed by the system, not improvised by the model.

cycle

Multi-Pass Extraction

The model does not fill the whole report in one shot. Tidemark breaks extraction into targeted passes and retries only what is still unresolved.

Development History

HOW WE GOT
TO WHERE
WE ARE.

Tidemark wasn't designed in a vacuum. Each version was a direct response to a real failure: in privacy, in reliability, in trust. This is the record of how it grew.

v1.0 Foundation

The concept proved.

First working report. 15 incident types. Single-pass extraction. The version that answered the only question that mattered: can a spoken account become a defensible record?

v2.0 Privacy Rebuilt

Regex wasn't enough.

Privacy layer rebuilt from pattern matching to structural NLP. Identity maps moved entirely to volatile RAM: no disk writes at any stage. The shift from "does it work?" to "is it safe enough to trust with real guest data?"

v2.4 Current

Three brains. One decision.

Neural model (BERT-Small ONNX) added alongside structural NLP and statistical filtering: all three must agree before a name is redacted. iOS native app. PDF and DOCX export. The version that ships.
